Scaling Plan

The API and ML services are stateless — all state is in Redis and PostgreSQL, and live alerts fan out via Redis pub/sub — so both scale horizontally behind a load balancer. Table 12.2 sketches the path from the prototype to national scale.

Scaling stages
StageLoadArchitecture
Prototype≈ 20 req/sOne instance of each service on a laptop (current).
Pilot≈ 200 req/s3 API + 3 ML replicas behind a load balancer; managed PostgreSQL with a read replica; managed Redis; hosted in an Indian cloud region.
Regional≈ 2,000 req/sRedis Cluster with per-user hash tags so a user's keys share a slot; monthly partitioning of Transaction and RiskDecision; autoscaling ML pods (one process per core).
National≥ 10,000 req/sKafka streams for durable, replayable events and streaming features; a feature store (online Redis + offline warehouse) to guarantee training/serving parity; multi-region active-active deployment.
