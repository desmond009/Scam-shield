Interview guide (semi-structured, 10–15 minutes)

  • Tell us about the last suspicious call or message you received. What made you suspicious — or not?
  • If you (or someone you know) paid a scammer: walk us through the moments before pressing Pay. What would have made you stop?
  • [Show HIGH-risk screen] What do you understand from this screen? What would you do?
  • [Show MEDIUM screen] Are the questions clear? Would you answer honestly if someone was on the phone with you?
  • For shopkeepers: which of your routine payments might look unusual to a computer?

Code Excerpts

Decision function (packages/shared/src/blend.ts)

export function blendScores(ruleScore: number, mlScore: number | null, t: Thresholds): number {
  const raw = mlScore === null ? ruleScore : t.ruleWeight * ruleScore + t.mlWeight * mlScore;
  return Math.round(Math.min(100, Math.max(0, raw)) * 10) / 10;
}

export function decide(input: DecisionInput): DecisionOutcome {
  const { thresholds: t } = input;
  let finalScore = blendScores(input.ruleScore, input.mlScore, t);
  const overrides: OverrideCode[] = [];
  if (input.payeeConfirmedFraud) {
    overrides.push("CONFIRMED_FRAUD_PAYEE");
    finalScore = Math.max(finalScore, CONFIRMED_FRAUD_FLOOR);      // 95
  }
  if (input.features.ctx_otp_or_app === 1) {
    overrides.push("OTP_REQUESTED");
    finalScore = Math.max(finalScore, t.highThreshold);             // at least HIGH
  }
  const reasons: Reason[] = [
    ...overrides.map((code) => ({ code, points: 100, vars: {} })),
    ...input.hits.map((h) => ({ code: h.code, points: h.points, vars: h.vars })),
  ];
  if (input.mlScore !== null && input.mlScore >= ML_REASON_MIN_SCORE) {
    reasons.push({ code: "ML_PATTERN", points: Math.round(input.mlScore * t.mlWeight),
                   vars: { mlScore: Math.round(input.mlScore) } });
  }
  return { finalScore, band: bandFor(finalScore, t), blocked: input.payeeConfirmedFraud,
           degraded: input.mlScore === null, overrides, reasons };
}

Occlusion explanation (services/ml/scamshield_ml/explain.py)

def top_contributions(artifact: dict, x: np.ndarray, k: int = 3) -> list[dict]:
    names = artifact["feature_names"]
    reference = artifact["reference"]          # a typical legitimate payment
    batch = np.repeat(x[None, :], len(names) + 1, axis=0)
    for i in range(len(names)):
        batch[i + 1, i] = reference[i]         # reset one feature per row
    p = artifact["raw"].predict_proba(batch)[:, 1]
    contributions = p[0] - p[1:]               # drop in fraud probability
    order = np.argsort(-contributions)[:k]
    return [{"feature": names[i], "value": float(x[i]),
             "contribution": round(float(contributions[i]), 4)}
            for i in order if contributions[i] > 0.005]

User Manual

Installation and start-up

  1. Install Docker Desktop (with Compose v2) and make.
  2. Clone the repository and run make demo. This copies .env.example to .env, builds and starts all six containers, and waits until the stack is ready. The first start takes 3–6 minutes because the ML container generates about 165,000 synthetic transactions and trains the model.
  3. Open http://localhost:3000. API documentation is at http://localhost:4000/docs.
  4. Useful commands: make ps (status), make logs, make test, make e2e, make loadtest, make train, make reset (deletes all data).

For payers

  1. Wallet shows your balance, spending over 30 days and recent payments with their risk band.
  2. Send money: enter the recipient's UPI ID — the recipient card shows whether you have paid them before and how long they have been on the platform — then the amount, and press Check & pay.
  3. Low risk: the payment completes immediately.
  4. Medium risk: read the reasons and answer the three questions honestly; press Re-check with my answers. You may then verify the recipient, cancel, or continue.
  5. High risk: the screen cannot be dismissed. The safest choice is Cancel and report this account. If you are sure you know the person, wait for the 10-second pause and retype their UPI ID exactly.
  6. Payment stopped: the recipient has been confirmed as a scam account; the payment cannot proceed.
  7. My Safety lists the warnings you received and the accounts you reported.

For analysts

  1. Open Alerts. New alerts arrive live (green Live indicator). Filter by status and band.
  2. Select an alert to see the amount, payer and payee, score breakdown (rules, ML, final), all reasons with technical detail, the model's top features and the payee's history.
  3. Add notes and choose Confirm fraud (labels the payment and blocks all future payments to the payee for every user) or Mark safe (closes the alert).

For administrators

  1. Simulator: run a scenario (normal, impersonation, mule collection, velocity drain, account takeover) and inspect each step's scores and reasons.
  2. Rules: enable/disable rules, change weights, points and parameters, blend weights and thresholds; the what-if panel previews precision, recall, false-positive rate, band mix and per-scenario effects before you save.
  3. Model: view the active model and its evaluation; press Retrain model to train on the synthetic data plus analyst labels.
  4. Health: monitor service status, circuit breaker, decisions by band, latency percentiles, ML outcomes, queues and the worker summary.

Troubleshooting

  • “Checked with safety rules only” on a decision means the ML service was unavailable; check make ps and the Health page.
  • Signing in with typed credentials in a new browser counts as a new device; use the one-click demo buttons for the registered device.
  • To start completely fresh, run make reset and then make demo.
